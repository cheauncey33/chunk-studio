# 标准值审查检索优化与测试集扩展方案

## 1. 目标

项目的最终目标不是回答一般性标准问答，而是审查检测报告中的标准要求是否引用正确：

```text
报告级产品参数
+ 检测项目
+ 报告中填写的标准要求
→ Query 改写
→ 检索标准 Chunk
→ 判断报告标准值是否正确
```

当前主要问题是正确证据 Chunk 不能稳定返回，模型判断本身暂不是主要瓶颈。因此现阶段重点是检索测试集建设和检索方案验证，不进入最终审查模型的生产集成。

## 2. 当前进度

### 2.2 报告级参数提取

字段值保留报告原始表达，不拆分独立单位。短路阻抗已从报告级参数中删除，因为它属于检测项目或测量结果。

## 3. 已验证结论

### 3.1 Top 20 必须考虑 Chunk 类型

统一 Top 20 会导致某一类型占据大部分候选。当前实验改为：

```text
table 独立召回
section 独立召回
→ 各自融合
→ 最终保留 10 table + 10 section
```

分类型召回解决了候选配额问题，但没有单独解决目标表在 table 类型内部排名过低的问题。

### 3.2 表题、表头字符串加分只对部分案例有效

轻量字符串实验结果：

| 案例 | 原始表格排名 | 重排后排名 |
|---|---:|---:|
| Pk，Q/GDW 表 6 | 31 | 14 |
| 外施耐压，GB/T 1094.3 表 2 | 25 | 9 |
| 雷电冲击，GB/T 1094.3 表 2 | 14 | 8 |

表头中的专用试验术语对外施耐压和雷电冲击有效，但“负载损耗”存在于大量性能表中，不能区分产品系列。

### 3.3 表题向量统一高权重不成立

临时表题、表头向量实验使用：

```text
表题向量排名       0.55
原始向量/RRF排名  0.30
表头向量排名       0.15
```

结果三个目标排名全部下降：

| 案例 | 原始排名 | 表题主导重排后 |
|---|---:|---:|
| Pk 表 6 | 30 | 26 |
| 外施耐压表 2 | 25 | 27 |
| 雷电冲击表 2 | 14 | 21 |

原因是标准表题经常过于泛化，或者仅描述产品范围；真正有辨识力的试验项目和参数可能在表头或正文中。该统一权重方案不应进入生产。

### 3.4 `table_target` Query 有潜力，但人工版本不能计入成绩

人工编写的 `table_target` 能明显提高目标表排名，但属于 oracle 上限实验，不能作为真实检索成绩。

合法的 `table_target` 必须只使用检索前可获得的信息：

- 报告原始型号；
- 报告级 Schema 参数；
- 检测项目；
- 物资对应的型号命名规则。

不得使用：

- 报告声称的标准答案作为目标条件；
- 从目标标准表反推的设备最高电压或适用等级；
- 人工提前知道的目标表标题。

### 3.5 型号命名规则能够改善表格检索

使用 JB/T 3837—2024 的 MinerU Markdown 解析：

```text
S20-M.RL-400/10-NX2
```

`qwen-flash` 生成的表格 Query 将 Q/GDW 表 6 单路召回到第 3；`qwen3.6-27b` 将其召回到第 2。

但当前型号解析仍有问题：

- 模型会补充缺省特征，但未给每项独立证据；
- evidence quote 可能是概括，不是 Markdown 中可搜索的连续原文；
- 型号身份解析可能混入损耗比例等性能规则；
- 等权 RRF 会把专用 `table_target` 的强结果稀释到第 13。

因此型号命名规则方向有效，但提示词证据约束和融合策略尚未完成。

## 4. 为什么暂停继续调权重

当前权重实验主要围绕三个已知失败案例：

- Pk；
- 外施耐压；
- 雷电冲击。

继续根据这三个案例调整标题、表头或 RRF 权重会产生小样本过拟合。即使三条全部进入 Top 10，也不能证明其他检测项目有效。

在扩大测试集之前，不应：

- 继续微调标题和表头权重；
- 为已知目标表增加专用规则；
- 把实验融合策略接入正式检索页面；
- 将人工 `table_target` 计入召回成绩。

## 5. 测试集扩展方案

### 5.1 报告范围

使用四份报告：

- HBJC；
- EZC；
- WHC；
- XYC。

第一步对另外三份报告复用 HBJC 的检测项目提取提示词，得到完整候选项目池。提取全部项目不等于全部制作金标。

### 5.2 第一版规模

建议每份报告选择 8～12 个案例，总计约 32～48 个案例。

每份报告尽量覆盖：

- 3 个数值参数表项目；
- 2 个试验电压或绝缘项目；
- 2 个规则或公式项目；
- 1 个首次/重复试验对照；
- 1～2 个报告特有项目。

### 5.3 案例类型

| 类型 | 典型项目 | 主要证据 |
|---|---|---|
| 数值参数表 | 空载损耗、负载损耗、空载电流、短路阻抗 | table |
| 试验电压表 | 外施耐压、雷电冲击 | table + section |
| 规则和公式 | 感应耐压持续时间、总损耗 | section + table |
| 产品条件限值 | 温升、声级、偏差 | table 或 section |

还需要覆盖：

- 型号能够完整解析与无法完整解析；
- 首次试验与重复试验；
- 同名项目的不同阶段；
- 单 Chunk 直接证据；
- 多 Chunk 组合证据；
- 正确证据只在表格；
- 正确证据只在章节。

## 6. 开发集、验证集和测试集

建议划分：

```text
开发集：HBJC
用于错误分析、提示词调整和方案实现

验证集：EZC
用于有限次数的方案选择和权重选择

测试集：WHC + XYC
最后运行，不根据结果继续调参
```

如果查看测试集后继续调整方案，WHC 和 XYC 应降级为开发数据，并重新准备未见过的测试报告。

## 7. 待比较的固定方案

扩大测试集后，固定比较以下方案：

### A. 纯向量基线

```text
production / semantic / keyword
→ 全类型向量检索
```

### B. 分类型召回

```text
table 独立召回
section 独立召回
→ 10 table + 10 section
```

### C. 分类型 + 模型生成 `table_target`

```text
型号命名规则解析
→ 模型生成 table_target
→ 作为独立表格检索路线
```

### D. 分类型 + `table_target` + 可解释重排

重排方案在扩大测试集前不固定具体权重。任何权重必须在开发集确定、验证集选择，最后只在测试集运行一次。

## 8. 评估指标

至少记录：

- Table Recall@10；
- Section Recall@10；
- Evidence-group Recall@20；
- MRR；
- 完整证据组召回率；
- 各 Query 路线独立命中率；
- 新增路线的独立贡献；
- 型号解析成功与失败情况下的召回差异；
- 检索失败类型：未进入候选池、类型内排名过低、融合后被稀释、适用条件缺失。

## 9. 型号命名规则文件的后续设计

当前项目没有正式知识库实体，`knowledge_categories` 只是文件标签。第一阶段可采用低复杂度方案：

```json
{
  "knowledge_categories": ["油浸式变压器"],
  "doc_type": "型号命名规则",
  "document_role": "model_naming_rule",
  "active": true
}
```

当一个类别存在启用的命名规则文件时：

```text
原始型号
+ 命名规则文件
→ LLM 型号解析
→ naming_rule_derived 产品特征
→ table_target
```

没有规则文件时跳过，不允许模型凭行业常识补全。

生产阶段应缓存解析结果：

```text
知识库类别
+ 命名规则文件 SHA-256
+ 原始型号
```

第一阶段不新增知识库表。只有在链路价值被扩大测试集证明后，再考虑正式 `knowledge_bases` 实体和命名文件外键。

## 10. 下一步执行顺序

1. 固化 HBJC 检测项目提取提示词；
2. 对 EZC、WHC、XYC 提取全部检测项目；
3. 生成四份报告的候选案例清单；
4. 按案例类型分层选择 32～48 条；
5. 为候选案例建立直接证据、辅助证据和不确定证据；
6. 使用稳定 locator 保存候选金标；
7. 冻结开发集、验证集和测试集；
8. 依次运行 A、B、C、D 四组方案；
9. 基于统一指标决定 Query 路线和融合策略；
10. 只有测试结果支持时，才把型号命名文件和检索管线接入产品。

## 11. 当前决策

- 保留分类型召回能力；
- 保留型号命名规则解析实验；
- `qwen3.6-27b` 作为下一轮型号解析提示词实验模型；
- 暂停继续调整标题、表头和 RRF 具体权重；
- 暂不修改知识库数据模型；
- 先扩大报告覆盖和测试集规模。
