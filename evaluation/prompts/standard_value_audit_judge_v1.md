# 检测报告标准要求审查 v1

判断报告填写的标准要求是否被候选标准 Chunk 支持。只能使用输入中的报告事实、型号解析结果和候选 Chunk，不得用常识补充标准值。

状态：
- correct：直接证据支持报告要求；
- incorrect：直接证据给出冲突数值、公式或适用条件；
- insufficient_context：候选中存在相关条件规则，但报告缺少决定适用性的参数；
- evidence_not_found：候选中没有足够证据。

表格可能需要结合容量、型号、联结组等选择行列。多个 Chunk 可以组成证据链。不要把报告声称的数值反过来当作标准证据。

产品专用标准表的适用性规则：
- 如果候选 Chunk 的标准号、表题、行列字段与输入中的报告事实或型号解析结果明确匹配，例如电压等级、容量、调压方式、铁心结构、能效等级/系列代号、联结组等，则可以把该 Chunk 作为产品专用直接证据。
- 不要因为候选标准不是国家标准就自动降级或拒绝。Q/GDW、JB/T、GB/T、GB 等标准的优先级只能依据输入证据中的适用范围、表题、引用关系和产品特征判断。
- 对空载电流、空载损耗、负载损耗等性能参数，产品专用性能参数表可以提供基准值；GB/T 1094.1 或 JB/T 501 等偏差/试验规则可以提供允许偏差。两类 Chunk 可以组合成完整证据链。
- 如果产品专用表已经通过表题和行列字段明确匹配样品，不要再要求额外证明“该标准是否适用”，除非候选中存在冲突的适用范围或产品结构条件。
- 如果产品专用标准表已经直接给出某试验项目的判定标准，应优先依据该产品专用表判断。不要再用通用标准中的结构分类规则要求额外的绕组、油箱或铁心结构映射，除非产品专用表自身也要求这些条件。
- 对 Q/GDW 12126.4-2024 中题名明确为“油浸式配电变压器”或具体油浸式配电变压器类型的试验项目/判定标准表，如果输入样品事实已经表明是油浸式配电变压器，应把该表作为产品专用判定依据；不要再要求证明其相对 GB/T 通用标准的强制优先级。
- reason 只能说明输入中明示的事实、型号解析结果和候选 Chunk 内容。不得在 reason 中使用或暗示“通常”“一般”“常见”“大概率”“往往”等未由输入证明的行业经验。

同报告上下文规则：
- 输入中如提供 peer_report_context，只能把它当作报告事实上下文，用于识别同一报告中已经出现的相关项目、分项值、频率、容量、电压、试验条件等。
- peer_report_context 不是标准证据，不能替代候选标准 Chunk。
- 对“总损耗”“频率范围”“试验持续时间”等依赖其他报告字段的要求，可以结合 peer_report_context 中的报告事实与候选标准 Chunk 或 manual_knowledge_rules 中的公式/规则判断；如果缺少候选标准公式/规则且没有适用的人工规则，仍应输出 evidence_not_found。

人工知识库规则：
- 输入中如提供 manual_knowledge_rules，可以把其中适用的规则作为项目人工维护的派生规则使用。
- manual_knowledge_rules 只能用于其 allowed_use 描述的计算关系、派生关系或固定项目规则，不能提供标准限值来源、产品适用性证明或候选证据中不存在的产品结构事实。
- 使用 manual_knowledge_rules 时，reason 必须明确写出使用了哪个 rule_id，并说明该规则只承担了什么推导作用。
- 对总损耗类要求，如果 manual_knowledge_rules 中存在适用规则，且候选标准证据或 peer_report_context 已分别给出 P0 与 Pk，则允许按该人工规则计算 P总 = P0 + Pk。

不得使用“通常”“一般”“常见”“大概率属于”等行业常识确认适用条件。只要标准规则依赖的产品结构在报告事实中没有明确给出，就必须输出 insufficient_context。

如果候选只给出了部分分项值，却缺少计算公式或另一项必需证据，且 manual_knowledge_rules 中也没有适用规则，不得据此判定报告正确或错误，必须输出 evidence_not_found。只有候选证据与适用人工规则足以构成完整推导链时才可判断。

如果目标要求包含具体基准值、限值或表格行列值，例如 0.16%、3.615 kW、35 kV 等，必须能在候选 Chunk、peer_report_context 或适用 manual_knowledge_rules 的派生结果中找到该数值来源。不得因为报告格式看起来符合偏差公式，就假设报告中的基准值是正确的。

严格输出 JSON：

{
  "status": "correct|incorrect|insufficient_context|evidence_not_found",
  "reason": "",
  "evidence_candidate_keys": [],
  "missing_context_fields": []
}
